# web — React · Vite · TypeScript

확정본 §7이 **"제품 등록 + 후보 선택 + variant/키워드/목표가 설정 화면은 1차 검증 전에 선개발"** 로 못박은 그 슬라이스에서 출발했다.

M1의 잔여 블로커가 전부 외부(토큰·키·승인)라, 그 뒤로도 코드로 갈 수 있는 화면은 계속 앞당겨 붙였다 — 확정본상 M3~M6인 판단 화면·구매 기록·미상 큐·중고·딜 보관함·우선순위·설정까지 전부 여기 있다(`working-area/decision-log.md`). 라우터는 안 들인다 — 화면 수가 늘어도 `App.tsx`의 탭으로 충분하다(URL이 필요해지면 그때 넣는다).

```bash
npm install
npm run dev      # http://localhost:5173 — /api 는 :8080(core)로 프록시
npm test         # Vitest
npm run build    # 타입체크(tsc --noEmit) + 프로덕션 빌드
```

## 배포

```bash
docker compose up -d   # http://127.0.0.1:3000
```

nginx가 정적 자산을 서빙하고 `/api`를 `core:8080`으로 프록시한다.

## 지금 되는 것

- **제품 등록**(REG-02): 가격축 **조합**대로 variant 생성(용량 2 × 색상 2 → 4개). 등록 전에 "생성될 variant N개"를 미리 보여준다. 별칭·수요축 모드(GROUPED/SPLIT, 축별 유형 선택).
- **등록된 제품 목록**: variant와 함께 **`variantId`를 노출**한다 — 기준가·신호·주기·구매 조회가 전부 이걸 요구하는데, 등록 응답은 `productId`만 준다.
- **등록 → 판단 흐름**: 등록에 성공하면 그 제품의 variant를 나열하고 "판단 보기" 버튼을 준다. **여럿이면 골라주지 않는다**(원칙 2).
- **판단 화면**(`decision/`): 신호등(SIG) · 핫딜 기준가/굿딜라인 · 갭 · 딜 주기(CAD) · 쿠팡 관측가(CMP-01) · 📌 핀 버튼을 한 화면에. 기간 P(3/6/12개월)는 **사용자 손잡이**(원칙 4) — 단 신호등은 core가 6개월로 고정하므로 기간이 다르면 그 사실을 화면에 밝힌다. 이상치 포함(참고용) 토글, 알림 정책 패널(목표가·기간·quiet hours·K·제외 키워드·수요축 필터)도 여기 있다.
- **구매 기록**(`purchase/`, PUR): 실지불가·구매일·관찰 기간을 기록하고, 구매별 관찰 문맥과 발급된 성적표를 한 줄로 보여준다. 날짜만 아는 구매 시각은 **23:59 KST**로 환산해 보낸다(V2 계약: 입력 계층 책임). 표시는 항상 KST(OPS-03).
- **미상 큐**(`review/`): 매칭 실패 딜·분포 하단 이상치가 쌓인다. 이상치는 승격(정상 딜로 표본 복귀)·기각(영구 제외) 둘 다, 미상 항목은 variant를 골라야 승격된다(안 고르면 기각만).
- **딜 보관함**(`watch/`): 지켜보고 싶은 딜을 핀으로 꽂아 활성/회고 탭으로 관리. [샀어요]를 누르면 판단 화면으로 이동해 구매 기록 폼이 프리필된다.
- **중고**(`used/`): 3계층 조건검색(필수 AND/보너스 OR/제외 NOT) 등록, URL·텍스트·수동 3단 평가기, 매물 메모·비교축·비교표.
- **우선순위**(`priority/`): 등록 제품의 대기열 순서를 손으로 정렬하고 수동 완료 표시.
- **설정**(`settings/`): 전역 제외 키워드(모든 제품에 공통 적용).

### 정직성을 순수 함수의 테스트로 못박는다

`decision/present.ts`·`purchase/present.ts`는 도메인 응답 → 문구 변환만 하는 순수 함수다. 렌더링이 아니라 **단위 테스트가** 규칙을 지킨다.

- SPARSE/NONE에선 통계 용어도 금액도 내지 않는다(테스트가 `\d{1,3}(,\d{3})+원` 패턴의 부재를 단언).
- 주기(CAD)에 "예상·예측"을 쓰지 않는다(단어의 부재를 단언).
- **`currentPrice === null`이면 미확립**이다(`docs/91` Q-53). core가 미확립이면 `currentPrice: null`·`gap` 두 leg도 null로 보낸다(갭을 아예 계산하지 않는다) — 갭을 그리지 않는다. 해석은 `currentPriceUnavailable` 한 곳(예전 sentinel 0 → 이제 타입상 null).
- 관찰 문맥의 세 모드는 배타이고 모드 밖 필드는 `null`이다. `null`을 "0"으로 읽지 않는다.

## 아직 안 되는 것 (정직하게)

- **네이버 후보 검색**(REG-01 주 경로): 네이버가 해당 검색 API를 종료했다(`docs/91` Q-3, 2026-07-31부). 지금은 **수동 입력만** — REG-01이 인정한 폴백이다. 대체 데이터 소스는 [`decisions-needed`](../working-area/decisions-needed.md) D-7 결정 대기.
- **접근 통제**(SEC-02): Basic Auth는 **구현됐으나 기본 off**다. `.env`의 `WEB_BASIC_AUTH_HTPASSWD`를 채워야 켜진다(`docker-entrypoint.d/40-basic-auth.sh`). compose는 `127.0.0.1`로만 개방한다. **HTTPS는 아직 없다** — 평문 HTTP에서 Basic Auth는 자격증명을 그대로 노출한다. 공개망 노출 전 `decisions-needed` D-4·`pre-deploy-checklist` §C.
- **쿠팡 크롬 확장 자체**: ingest 수신 REST는 완성됐지만 송신부(manifest·content script·DOM 파서)가 없다 — 실 쿠팡 페이지 DOM fixture 없이 만들면 "우연히 옳은 코드"가 된다. 확장 부재 시 반자동 붙여넣기 폴백 폼도 아직 없다(인증 경계 결정 대기, D-9).
- **백필 표기**(REG-04): 백필 자체가 미구현.

## 설계 메모

- **CORS가 필요 없다.** 운영에선 nginx가, 개발에선 Vite 프록시가 `/api`를 core로 넘긴다. 브라우저에겐 동일 오리진이라 교차 출처 요청이 발생하지 않는다 — core에 CORS 설정을 추가할 이유가 없고, 개발과 운영의 동작이 같다.
- **nginx는 core 없이도 뜬다.** `proxy_pass`에 리터럴 호스트를 쓰면 기동 시점에 DNS를 해석하다 실패해 web 전체가 죽는다(정적 페이지조차). 업스트림을 변수로 두고 `resolver`를 지정해 **요청 시점**에 해석한다 — core가 없으면 `/api`만 502다.
- `src/api/types.ts`는 **core 컨트롤러를 직접 읽고 옮긴 계약**이다. 추측하지 않았다.
- 통계 필드가 `null`인 것은 버그가 아니라 **도메인 계약**이다 — 표본이 빈약하면 통계 용어를 쓰지 않는다(절대 원칙 1). 타입이 null을 감추지 않는다.
- `{code, message}`가 아닌 실패(바인딩 오류·500)도 삼키지 않고 `HTTP_{status}`로 살린다.
