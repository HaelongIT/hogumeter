# 21. TDD 가이드라인 & 교훈 메모리 프로토콜

## 사이클 규율
1. 요구 ID(예: BM-06) 선택 → 수용 기준을 테스트 목록으로 분해(테스트 이름 먼저 나열)
2. Red: 실패 테스트 1개 작성 (컴파일 실패도 Red)
3. Green: 통과하는 최소 구현
4. Refactor: 중복 제거·이름 정리. 테스트 그린 유지
5. 커밋: `[BM-06] red/green/refactor: ...` — 사이클 단위 커밋 권장
- 프로덕션 코드를 테스트 없이 작성했음을 발견하면: 멈추고 테스트를 소급 작성 후 lessons에 기록.

## 테스트 피라미드 (이 프로젝트의 형태)
- **단위(대다수)**: domain 패키지 — 기준가·이상치·매칭·알림·3계층 필터·생애주기 diff. IO 0, Clock 주입, 파라미터라이즈드 적극 사용.
- **파서 golden 테스트**: fixture HTML → DTO 스냅샷 비교. fixture는 스파이크에서 채취하고 `tests/fixtures/{site}/{케이스}.html`로 버전 관리. 사이트 구조 변경 시 fixture 갱신 + 변경 내용 field-notes 기록.
- **어댑터 슬라이스**: @DataJpaTest+Testcontainers(persistence), @WebMvcTest(web), WireMock(naver). 얇게.
- **통합(소수)**: compose 기반 스모크 — "글 fixture 주입 → 매칭 → 병합 → 알림 판정 → 발송 fake 검증" 종단 1~2본.
- **금지**: 실 사이트 네트워크 호출 테스트(스파이크 스크립트는 tests 밖 `spikes/`에 격리), 시간 sleep 기반 테스트, 순서 의존 테스트.

## 테스트 데이터 원칙
- 도메인 테스트는 빌더/픽스처 함수로 가독성 확보 (`aDealEvent().withPrice(890_000).crossVerified()`).
- 경계값을 요구 문서에서 직접 도출: K_display 3/5/10, n=0/1/4/5/7, 윈도우 경계, quiet hours 정각, ±α 경계.
- 확률·랜덤 없음. 모든 테스트는 결정적.

## 교훈 메모리 프로토콜 (CLAUDE.md 규정의 상세)
**언제 기록하나**: (a) Red가 예상과 다르게 실패/성공했을 때 (b) 버그 수정 시 (c) 리팩토링에서 설계 냄새를 발견했을 때 (d) 외부 세계(사이트·API)가 문서·가정과 다르게 동작했을 때 (e) 같은 실수를 2번째 했을 때(즉시 규칙 승격 대상).

**어디에**:
- `docs/99-lessons.md` — append-only 로그. 엔트리 형식:
  ```
  ## 2026-07-10 | BM-03 매칭
  증상: 용량 토큰 "1TB"가 "1테라"와 미매칭
  원인: 정규화 사전에 한글 단위 부재
  교훈(규칙): 숫자+단위 정규화는 한/영 양방향 사전 필수. 새 단위 발견 시 사전+테스트 동시 추가
  테스트: NormalizerTest#koreanCapacityUnits
  ```
- `docs/98-field-notes.md` — 사이트/API별 실측 사실(셀렉터, 응답 특성, 쿼터 실동작, 차단 징후, fixture 채취일).
- 반복 적용 가능한 규칙이면 3계층 중 하나로 승격(CLAUDE.md가 기본값이 아니다): **언어 무관+매 세션
  필요**만 CLAUDE.md `## 축적된 규칙`, **언어·디렉토리 한정**은 `.claude/rules/<scope>.md`,
  **테스트 작성 기법·결함 패턴**은 이 문서 자신(아래 새 절) — 특정 사이트 한정 실측은 field-notes에 유지.

**세션 훅**: 세션 시작 시 두 파일을 읽는다. 세션 종료(또는 큰 작업 완료) 시 "이번에 기록할 교훈이 있는가"를 자문하고 없으면 없다고 넘어간다 — 억지 기록 금지, 누락 금지.

## 테스트 결함 패턴 (교훈에서 승격)
> 언어 무관 테스트 작성 기법·결함 패턴. 출처는 `docs/99-lessons.md`. CLAUDE.md `## 축적된 규칙`의
> 3계층 승격 경로 중 세 번째 목적지다(`.claude/rules/claude-md-editing.md` 참조).

- **읽기만 하는 테이블·큐·포트를 보면 "누가 여기에 쓰는가"를 프로덕션 코드에서 찾아 이름을 댄다.** 못 대면 그 기능은 죽어 있다 — 테스트의 `save(...)`나 fake의 반환값은 생산자가 아니다. `alert_policy`는 읽히기만 해서 목표가 알림이 발화할 수 없었고, 트리거가 없어 `raw_deal_post`는 소비되지 않았으며, 모든 테스트는 GREEN이었다.
- **결함을 찾았으면 그 거울상을 찾는다.** "읽기만 하는 포트"를 찾았으면 다음은 "쓰기만 하는 포트"다(`review_queue_item` — 쌓이는데 볼 수가 없었다). 그 다음 거울상은 "호출자 0인 순수 함수"다 — 소비처 0 감사는 타입·테이블만이 아니라 함수에도 돌린다(`effective_interval_with_robots`는 GREEN인 채로 robots의 `Crawl-delay`를 한 번도 지키지 않았다). 테스트는 호출자가 아니다. 소비자를 만드는 일은 생산자를 검사하는 일이다 — 큐를 읽는 순간 큐가 어떻게 채워지는지 드러난다. 드러난 중복·유실을 조용히 정리하지 말고 세어서 노출한다(접기만 하고 세지 않으면 결함이 사라진 것처럼 보인다).
- **포트를 도입하면 포트의 계산이 아니라 포트의 주입을 테스트한다.** 주입을 보지 않는 단위 테스트만 짜면 "GREEN인데 죽어 있다"를 한 층 위에 다시 만든다. 배선을 지웠을 때 RED가 되는 테스트가 하나는 있어야 하고, 그 사실은 뮤테이션으로 증명한다.
- **"컬럼이 있다"는 "값이 도달한다"가 아니다.** DDL → 엔티티 매핑 → 도메인 필드 → 생성 지점 → 표시, 다섯 구간 중 하나만 끊겨도 값은 사라지고 예외도 로그도 남지 않는다(조건 태그가 `raw` jsonb에 갇혀 표본의 1할이 조건부 가격인 채로 기준가에 들어갔다). 저장 계약이 있는 필드는 DDL이 아니라 최종 소비처에서 거꾸로 추적한다.
- **임계값이 있는 경로는 임계를 넘겨야 한 번이라도 돈다.** `n ≥ 5`·`연속 3회` 같은 조건은 종단 테스트의 최소 시나리오("딜 1건")에서 영원히 거짓이라 그 아래 코드는 한 번도 실행되지 않는다(🔥 이상치 경로가 그랬다). 각 임계를 넘기는 시나리오를 하나씩 만들고, 그때 옆의 다른 임계(병합 허용폭 등)도 피한다.
- **분기 커버리지를 실데이터로 센다.** "어느 가지가 몇 번 참이 되는가"를 golden 전수로 측정하면 한 번도 실행되지 않은 가지가 드러나고, 그 가지는 검증된 적이 없으므로 결함의 서식지다(가격 폴백이 0번 돌면서 `RTX 5070`을 5,070원으로 읽고 있었다). 거짓 값을 만드는 가지와 값을 못 만드는 가지 중에서는 후자를 택한다 — "놓침 > 오알림"은 딜을 놓칠 때의 말이지 값을 지어낼 때의 말이 아니다(지어낸 값은 조용히 기준가를 망치고 로그도 없다).
- **차단·필터 장치는 "무엇을 통과시켜야 하는가"를 먼저·더 많이 테스트한다.** 오차단은 조용히 작업을 마비시키지만 미차단은 다른 방어선이 받는다.
- **감지기가 무엇을 못 보는지 세어 보라.** 이미 겪은 결함 목록을 감지기에 대 보고 "이 결함이 나면 어느 신호가 켜지는가"를 묻는다. 하나도 안 켜지면 그건 감지기가 아니라 장식이다(드리프트 감지는 `deals==0`만 봤는데, 파서 결함 다섯 중 셋은 딜 수가 그대로인 채 값만 틀린 부류였다).
- **환경 의존 설정(타임존·로케일·인코딩)은 "지금 환경의 값과 같은가"가 아니라 "요구사항이 명시한 고정값과 같은가"로 단언한다.** 전자는 개발 기계가 우연히 운영과 같은 설정이면 결함을 통과시킨다 — `Clock.systemDefaultZone()`이 컨테이너에선 UTC인데 한국인 개발자 기계는 이미 KST라 quiet hours가 9시간 어긋난 채 전 테스트가 GREEN이었다. `assertThat(zone).isEqualTo(ZoneId.of("Asia/Seoul"))`처럼 우변에 리터럴을 둔다.

## 모듈별 최소 시나리오 카탈로그 (첫 테스트 목록의 씨앗)
- benchmark: SUFFICIENT/SPARSE/NONE 3단 출력 계약, 자동확장 발동·상한, 백필 혼합 n 계산, 이상치 제외 후 median, goodDealLine은 교차검증만
- matching: 별칭 히트, 미상 강등, CANDIDATE 경계, 확정 시 사전 축적
- deal: 병합 성립/불성립(±α·윈도우), 미상 잠정 병합→확정, 상태 전이 전수(NEW→ACTIVE→VERIFIED→ENDED + PRICE_CHANGED)
- alert: 트리거 매트릭스, 1발 원칙, quiet 보류·플러시·🔥관통, 후속 자격
- used: 3계층 조합, SORT/TRIGGER 분기, 목록 diff 4종(신규/변동/SOLD/끌올)
